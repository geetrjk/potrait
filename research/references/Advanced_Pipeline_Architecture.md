# Advanced Architecture Plan: Modular Identity-Transfer Pipeline (V6)

This architecture defines a production-grade identity transfer system characterized by modular logic, rigorous observability, and **Human-in-the-Loop (HITL)** orchestration. It explicitly bounds automated operations by treating the GitHub repository as the infallible source of truth, ensuring that remote execution environments (like SimplePod) remain transient testbeds rather than permanent homes for workflow logic.

## 1. Remote Execution & Human-in-the-Loop Orchestration

The system executes the high-VRAM identity workflows securely in the cloud via **SimplePod**. The system *does not* manage the pod's underlying lifecycle; it assumes the pod is externally provisioned and active.

### Deployment & Git source of truth
*   **SSH Deployment First:** The GitHub repository is the absolute source of truth. Before execution, the agent pushes all current workflow `.json` files, custom scripts, and configs from GitHub directly onto the remote SimplePod instance via SSH.
*   **Transient Remote State:** The remote instance is treated strictly as a compute engine and visual canvas, not a persistent repository. 

### Human-in-the-Loop (HITL) Workflow
*   **ComfyUI as the Visual Workspace:** While the pipeline relies heavily on saved output artifacts (tensors and PNGs), the ComfyUI browser interface remains the primary interactive workspace. All intermediate outputs across the modular stages remain visible on the ComfyUI canvas for manual inspection.
*   **Manual Intervention & Node Adjustment:** At any point, the human operator can pause automated execution, open the SimplePod ComfyUI browser link, and manually tweak node parameters (e.g., dialing a ControlNet strength or swapping a LoRA) to perfect the lighting or identity match.
*   **Save & Sync Protocol:** If manual changes are made in the ComfyUI UI, the automated system *will not* proceed iteratively until the operator (or an assisting agent) explicitly saves the updated workflow `.json` from the browser and syncs it back into the GitHub repository. All future automated deployments will pull from this freshly updated Git truth.

## 2. Structured Output & Artifact Preservation

Alongside the real-time visual inspection in the ComfyUI browser, every pipeline execution enforces strict structural saving to enable modular debugging and programmatic tracking.

**Directory Structure:**
```
outputs/run_<timestamp>/
├── module0_preprocessing/
├── moduleA_template/
├── moduleB_identity/
├── moduleC_composite/
├── moduleD_final/
└── evaluation_report.md
```

## 3. Advanced Pipeline Architecture & Data Flow

The system is strictly divided into six sequential blocks. Intermediate outputs generated by these blocks are viewable dynamically in the ComfyUI browser *and* saved directly to the localized path above via SSH/download protocols.

### Module 0: Input Preprocessing (The Ingestion Block)
*   **Role:** Universal ingestion handler stabilizing resolution (1MP) and formatting.
*   **Outputs & Save Logic:** `module0_subj.png` and `module0_tgt.png`.
*   **HITL Check:** Visually confirmed in the browser if faces/templates are deformed or improperly cropped.

---

### Module A: Target Stage Composition (The Environment)
*   **Role:** Prepares the environment/character template from standard disk inputs (or generative fallback).
*   **Outputs & Save Logic:** `moduleA_base.png`, `moduleA_mask.png`.
*   **HITL Check:** Inspect the ComfyUI canvas to ensure the semantic bounding area matches the base template body. Adjust mask dilations manually if required, save the JSON, and commit to Git.

---

### Module B: Identity Isolation (The Subject)
*   **Role:** Extracts the user's face perfectly using SAM2.
*   **Outputs & Save Logic:** `moduleB_crop.png`, `moduleB_mask.png`.
*   **HITL Check:** Browser/agent inspection to verify the mask strictly captures head features devoid of background bleed.

---

### Module C: Hybrid Harmonization (The Integration)
*   **Role:** The Subject successfully overrides the Stage identity via Flux 2 Klein inpainting and PuLID conditioning.
*   **Execution:** Composites Stage + Face, routes to Flux Inpaint via the facial mask, and drives lighting/identity matching at a 0.5–0.8 Denoise.
*   **Outputs & Save Logic:** `moduleC_harmonized.png`.
*   **HITL Check:** The most critical manual review phase. The operator uses the ComfyUI UI to perform a strict likeness comparison against the raw subject. If identity drift occurs, the user adjusts PuLID weights/Denoise sliders, downloads the new workflow JSON, and syncs it to GitHub.

---

### Module D: API-Augmented Upscaling (The Polish)
*   **Role:** Cloud-based upscale (Nano Banana Pro) offload for 2K/4K detailing.
*   **Outputs & Save Logic:** `moduleD_upscaled.png`.

---

### Module E: Evaluation / Validation (The QA Block)
*   **Role:** Step-by-step review interface synthesizing both artifact-based evaluation and contextual browser review.
*   **Responsibilities:** 
    *   Automatically ingest all saved outputs (`module0` through `moduleD`).
    *   Present a structured HTML gallery/Markdown report.
    *   This validation supplements the live ComfyUI browser inspection, giving the operator an immediate "post-mortem" array combining the raw inputs dynamically against the hybrid outputs to spot drifting across the entire branch sequence.

## 4. Security & Git Hygiene Compliance

*   **Zero Personal Data:** All workspaces are scrubbed of personal URLs.
*   **`.env` Centralization:** A `.env` file (strictly added to `.gitignore`) stores environment details like the `GITHUB_REPO_URL` and `NANO_BANANA_API_KEY`, which are ingested via SSH during deployment but never baked into the workflows.
